# Architecture decisions

1. Pin the decision to one outcome and cite constraints from the current code and issue. Identify who can approve the decision.
2. Compare viable options against correctness, compatibility, operating cost, reversibility, and migration effort. Include the current design where it remains viable.
3. Describe the recommendation, uncertainties, the test that could change the recommendation, and how to recover or reverse the change.
4. Record the agreed decision where the team already tracks the work. Distinguish a private fixture choice from a commitment for a hosted pilot.
