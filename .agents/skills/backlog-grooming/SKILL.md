# GitHub backlog

- Check open and recently closed issues and related PRs before creating or updating work. Verify the shipped behavior before describing an issue as resolved.
- Give each issue one outcome. Include evidence, acceptance tests, dependencies, and a specific approval boundary when applicable.
- Group cross-repo work under a coordinating issue and link the issues that carry each repo's work. Identify parallel work and hard dependencies.
- Use the GitHub connector or the configured Git workflow. Make updates when the user authorizes them and verify that the issue links and states match the requested work.

Use the [issue pattern](references/issue-pattern.md) when a ticket needs more structure.
